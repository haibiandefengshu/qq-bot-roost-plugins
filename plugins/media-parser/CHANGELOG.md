# Changelog

## 0.2.0 — 2026-11-25

### 静默启动与进程

- 统一托管 Python 子进程参数：Windows 使用 `windowsHide: true`、`detached: false`、`shell: false` 和独立日志；其他平台保留相应生命周期策略。
- 引擎准备、依赖修复、启动/停止/清理仍由现有托管服务处理，健康实例复用和归属校验不变。

### B 站登录与共享凭据

- 新增用户主动扫码登录、取消、检查、手动 Cookie 和退出共享登录；二维码只以内存 PNG data URL 或原生图片回复提供。
- 登录成功不自动开启私信提醒，也不自动开启 Cookie 增强解析。
- 共享 Cookie 仍由 `settings.js` 的串行原子写入管理；退出登录只清除本插件共享值，不调用全站注销。
- 旧布局中的 B 站 Cookie 归一化为单一根位置，其他平台凭据保持不动。
- 迁移旧配置中的唯一登录值时，先原子保存凭据，再清理旧来源；磁盘失败和迁移期间停用插件不会提交迟到的清理。

### B 站私信提醒（默认关闭）

- 新增 `biliDmEnabled`、`biliDmPollSeconds`（60～1800）、`biliDmIncludeSystem` 配置。
- 新增独立私信运行时：会话发现、首次基线、反向消息分页、持久化游标、账号隔离、请求预算与网络退避。
- 私信状态使用 `bili-dm-state.json`（`schemaVersion: 1`），按 UID 分区，未完成消息与投递分段串行原子保存。
- 新增主人 C2C 绑定、稳定投递键、分段正文、只读账本核对、待发送/待核对/未知分类和被动领取。
- 私信失败、状态损坏、登录失效或网络故障不会禁用原有媒体解析；`runtime.ready` 不因私信失败而拒绝。
- 热重载先取消旧代次网络/扫码，并在新设置与私信状态加载前等待旧代次存储写入尾部；已经进入宿主发送的动作只通过账本核对，不整批补发。
- 退出登录会提示共享 Cookie 对增强解析的影响；暂停提醒保留账号、绑定和进度。

### 管理页与命令

- `/解析 私信` 在媒体链接处理前分发，支持绑定、登录、状态、开、关、检查、测试、待发、领取、查看和退出登录。
- 所有私信子命令要求普通 C2C 且 `ctx.isOwner(msg.userId)`；群聊只提示移到私聊，非主人只得到权限提示，不接受请求体或聊天文本提供的目标。
- 新增认证前缀内的 `/bili/login/*` 与 `/bili/dm/*` 维护路由；写操作使用 POST/PUT，不提供页面绑定、正文、发送者或目标查询路由。
- 管理页新增登录、二维码、手动 Cookie、提醒设置、分离状态、积压/核对、测试通知；页面不读取私信正文，QR 只在专用登录响应中返回。
- 公开 `/status`、`/config`、仪表盘和媒体任务记录不包含私信绑定、UID、发送者、正文或内部运行时对象。

### 运行时复核修复与群目标选择

- 旧代次命令在异步账号检查或停用后不再写入配置；设置保存增加可选 `isActive` 和提交 guard，在串行队列内及文件重命名前复核，初始加载继续先等待旧代次写入尾部。
- 所有私信命令要求普通 C2C 且 `chatId === userId`（缺失 `chatId` 时使用原生 `userId`），并在异步操作后复核活跃代次与当前主人；二维码不会发到伪造会话。
- 私信状态只输出有限安全码、安全发现阶段、脱敏目标和白名单字段，不再复制任意 `reasonCode`、`errorCode`、`errorSummary` 或 `discovery.phase`。
- 领取和重复查看已在宿主被动回复中发送内容，命令不再追加第五段缓冲回复；查看支持可选数字页码和精确续页提示，前缀动态取自宿主。
- 管理页测试通知只委托已保存绑定，不再伪造 QQ 入站消息。
- 退出登录先暂停私信并取消扫码，再等待配置保存；保存或清除 Cookie 失败会明确拒绝，不显示虚假成功。
- 共享 Cookie 版本变化会标记增强解析需要重启；停用代次时移除该订阅。
- 管理页 `/bili/*` 错误统一为有限安全文本，不序列化原始接口错误。
- 新增管理页“发送到群”复选框、单个群选择框、刷新群列表和单独保存目标；默认仍是主人 C2C，管理命令和领取仍在主人私聊。
- 新增 `bili-dm-groups.js`，只通过宿主 `ledger.stats()?.byChat` 的群类型行、运行时普通群消息观察缓存（最多 200）和 `ctx.getGroup` 校验群存在且启用；不读取宿主存储路径或群正文。
- 新增认证路由 `GET /bili/dm/groups` 和 `PUT /bili/dm/target`；后者只接受 `sendToGroup`/`groupId`，验证现有主人绑定后调用后续投递模块的 `configureTarget`，缺失时安全失败。
- 接收目标变更冻结旧目标未尝试批次，不自动补发 `sending`、`pending` 或 `unknown` 结果。真实群发送仍**待联调**。

### 文档与测试

- 新增 `TEST-REPORT.md`、`MIGRATION-ROLLBACK.md`，更新 `README.md`、`SOURCES.md`。
- 新增 Node 集成测试，覆盖主人 C2C 门禁、全部命令、媒体开关关闭、Python 不可用、热重载写入交接、旧代次停用、请求体目标伪造、路由白名单和响应/页面泄漏。
- 新增 `test/bili-dm-groups.mjs` 和 `test/settings-lifecycle.mjs`，覆盖群候选过滤与宿主复核、200 条观察缓存、跨重载保留、目标保存和缺失投递 API 的安全失败，以及设置停用代次、提交 guard、写入交接和 flush 顺序。
- `VERSION`、插件入口版本和 `package.json` 同步为 `0.2.0`；引擎服务身份协议仍为 `0.1.0`，未做无关升级。
- GUI 冷启动、真实 B 站账号扫码/读取和真实 QQ C2C 投递仍为**待联调**，自动化测试不代表这些真机验收已通过。
